# Security threat model — Phase 7

## Scope and assumptions

Reviewed source, scripts, configuration, tests, and local fixtures at starting HEAD `17853aebe46600d113b6a5e8c59422cc8a03a6c3`. This is a static/local audit, not a penetration test or proof of deployed configuration. Secrets and customer records were not printed. No live services, production data, or third-party accounts were mutated.

## Assets and trust boundaries

| Area / asset | Entry point and boundary | Threats considered | Existing controls and evidence | Gap / residual |
|---|---|---|---|---|
| Public preview/contact forms and attachments | `/api/contact`; untrusted browser → Worker/email or configured provider | Oversize/malformed input, spoofed files, cross-site submissions, flooding, mail header injection, provider outage | Cross-site guard, 22 MiB request/4 MiB per-file limits, extension/MIME/magic-byte validation, text bounds, honeypot, rate-limit bucket, normalized filenames, preview recipient isolation; `check:contact`, `check:attachment-security` | Size is rechecked after form parsing when length omitted; upstream platform request limit is also relied on. Delivery is configuration-dependent and not live-tested. |
| Checkout/invoices/payments | `/api/invoices`, `/api/checkout`, `/api/checkout/capture`; browser capability token → D1/KV → PayPal | Unauthorized invoice creation, tampered amounts, IDOR, replay/races, wrong merchant/currency/order/capture, false paid status, provider timeout | Admin secret required; signed expiring invoice link; server-side amount; stable PayPal request ID; D1 conditional transitions and unique order/capture/event keys; capture re-read/verification; private no-store responses; timeouts; mocked negative/positive checks | Shared admin secret is a capability, not per-user identity or role system. Live provider and remote ledger not tested. |
| PayPal webhooks | `/api/paypal/webhook`; public provider callback → PayPal verification API → invoice ledger | Forged/replayed webhook, event tampering, certificate URL SSRF, mismatch or duplicate payment | Header shape limits; HTTPS PayPal cert-host allowlist; PayPal server-side signature verification; event parsing; invoice/order/amount/currency cross-check; independent order capture verification; unique event key; transactional D1 ledger; 256 KiB cap | Webhook credential and configured webhook ID/deployed endpoint were not validated; sandbox explicitly not run. |
| Conferbot webhooks/leads/messages | `/api/integrations/conferbot/webhook`; cross-site signed provider → intended `LEAD_DB` | Forgery, oversized body, wrong bot, replay, PII overcollection, partial writes/lost retries, unwanted email | Raw-body HMAC SHA-256, bot ID and feature gates, 256 KiB bound, deterministic unique event keys, redaction before storage, parameterized D1 statements, notification outbox/idempotency, flag-off default. `LEAD_DB` absent from `wrangler.jsonc`; isolated in-memory tests | Fixed premature `processed` marking; integration is not proven active. Notification delivery/outbox retry operations are not a managed background worker in this repo. |
| Reviews/admin moderation | `/api/reviews`, `/api/reviews/moderate`; public submission and email-link capability | Spam, stored XSS, link-scanner mutation, unauthorized approval/rejection, replay | Input bounds, rate limit, queued/unpublished reviews, escaped confirmation HTML, GET only displays confirmation; POST requires signed moderation capability; key checked and status transition is one-time; no-store | Capability URLs remain sensitive; mail/provider delivery and current review permissions/source totals are unverified owner decisions. |
| RUM/analytics and consent | `/api/rum`, consent-controlled browser loaders → analytics vendors | Cross-site beacon abuse, oversized payload, PII leakage, consent bypass | Same-site guard, payload schema/size/rate checks, logs only path/sample/metrics (not user payload), analytics loaders consent-gated; e2e reject/accept coverage | Analytics account/network delivery not live-verified. CSP still includes `unsafe-inline`; nonce/Trusted Types are owner-gated in SEC-01 docs. |
| Cloudflare Worker, KV, D1, email binding | `wrangler.jsonc`; runtime bindings and environment variables | Preview-to-production leakage, missing binding behavior, unsafe queries, migration mistakes, secret exposure, cache leakage | Separate preview KV/D1 IDs; preview mail recipients empty/fail-closed; lead D1 deliberately omitted until real DB exists; invoice and lead migrations separated; SQL parameters bound; private responses no-store; secrets supplied at runtime | No live dashboard/secret/binding inspection. D1 backup/reconcile remote commands explicitly owner-gated and not run. |
| Build, CI, deployment | `.github/workflows/ci.yml`, package scripts, OpenNext/Wrangler | Dependency compromise, untrusted CI permissions, accidental production deploy/migration | CI read-only contents permission, pinned action SHAs, PR/main CI, test/build checks; deployment scripts separate; no deployment run | Full npm audit has moderate dev/build findings; Cloudflare account access/policies not assessed. |
| Session/auth/authorization | Application routes and admin APIs | BOLA, privilege escalation, insecure session/cache/CSRF | No customer login/session/role system or customer-object API found in reviewed API surface. Invoice admin uses dedicated secret; invoice access uses signed invoice-specific token; moderation uses signed capability | Capability-secret management/rotation and owner operational access are outside repository evidence. |

## Trust-model notes

- Public application behavior alone does not prove provider activation. Conferbot has a flag and secret gate but no configured `LEAD_DB` binding here. The PayPal API code can default to the live API host when configured; no live request was made.
- KV is used for rate limits/reviews/cache; D1 is used for invoice ledger. Invoice and lead data stores are intentionally distinct.
- Cloudflare security headers are configured in the repository; zone-level header state was not independently queried in this audit.
- SQL in reviewed ledger modules uses prepared statements and bound values. No dynamic user-supplied SQL was found.
